# 앙상블 메이 공식 홈페이지

Next.js 로 만든 사이트입니다. 빌드하면 서버가 필요 없는 정적 파일이 나옵니다 —
페이지마다 진짜 HTML 이 만들어지므로 네이버·구글이 내용을 그대로 읽습니다.

## 시작하기

```bash
cd web
npm install       # 처음 한 번만
npm run dev       # http://localhost:3000 에서 고치면서 보기
npm run build     # web/out/ 에 배포할 파일이 떨어집니다
```

## 폴더

```
web/

  app/style.css  사이트 전체 스타일 (1420줄, 이 문서가 설명하는 그것)
  components/  헤더·푸터·라이트박스·문의 팝업 같은 공용 조각
  public/      사진·영상·파비콘
```

json 에 경로를 적습니다.

## 구조

상단 메뉴는 5개입니다. 왼쪽은 로고 마크 + `Ensemble M.A.Y` 워드마크입니다.

```
◪ Ensemble M.A.Y             Home  About  Concert  Gallery  Contact
```

> 로고를 눌러도 홈으로 가지만, 로고가 홈 링크라는 걸 모르는 분이 많아
> `Home` 을 따로 두었습니다.

### 모바일 메뉴는 오른쪽에서 나오는 서랍입니다

900px 아래에서는 내비가 숨고 버거 단추가 나옵니다. 누르면 **화면을 다 덮지
않고 오른쪽 일부만 차지하는 판**이 밀려 들어옵니다(`min(72vw, 320px)`).
왼쪽에 보던 화면이 남아 있어서 어디에 있다가 열었는지 감이 끊기지 않습니다.

- **오른쪽에서 나오는 이유** — 여는 단추(버거)가 오른쪽에 있습니다.
  눌린 자리에서 물건이 나오는 편이 방향이 자연스럽습니다.
- 닫기: **X 단추 · 서랍 바깥의 어두운 막 · ESC · 항목 선택** 네 가지 모두
- X 는 버거가 있던 자리에 그대로 둡니다 — 같은 자리를 다시 누르면 닫히는
  셈이라 손이 헤매지 않습니다
- 너비를 바꾸려면 `style.css` 의 `.menu__panel` `width` 한 줄입니다

> 서랍의 `z-index` 가 상단 바(300)보다 높습니다(310). 아래에 깔면 홈 첫
> 화면에서 문제가 생깁니다 — 그때 상단 바는 글자가 흰색이라 흰 서랍 위에
> 겹치면 버거가 보이지 않습니다.

> 헤더에는 `[입단 문의]` 버튼이 없습니다. 입단 문의는 히어로와 하단 CTA,
> 그리고 Contact 페이지에서 받습니다. 헤더에도 두고 싶으면
> `<button class="btn btn--solid" data-open="mdl-enroll">입단 문의</button>` 를
> `.nav` 뒤에 붙이면 됩니다 (6개 파일 모두).

### 왜 Enroll 을 따로 두지 않았나

입단과 자선 공연은 같은 메일함(`ensemblemay2025@gmail.com`)으로 갑니다.
내비 항목 두 개가 한 편지함을 가리키면 헷갈리기만 합니다.
대신 **헤더 버튼이 입단**, **내비 Contact 가 전체 문의**를 맡습니다. 페이지를 늘리지 않고 같은 효과를 냅니다.

메일 제목은 링크에 미리 박아두었습니다. 받는 쪽에서 바로 분류됩니다.

```
[입단] 문의
[자선 공연] 문의
```

## ★ 전화번호 넣기 (공개 전 필수)

`web/content/ 의 json 파일` 맨 위 한 줄입니다. **여기만 채우면 사이트 전체 팝업에 반영됩니다.**

```js
window.CONTACT = {
  tel:   "010-1234-5678",              // ← 여기
  email: "ensemblemay2025@gmail.com"
};
```

비워두면 팝업에 *"전화번호를 아직 넣지 않았습니다"* 라고 나옵니다.
없는 번호를 임의로 넣지 않으려고 이렇게 해두었습니다.

## 문의 팝업

`입단 문의` · `자선 공연 문의` 버튼을 누르면 까만 반투명 화면 위에 카드가 뜹니다.
닫기는 **X 버튼 · 까만 배경 클릭 · ESC** 세 가지 모두 됩니다.
닫으면 눌렀던 버튼으로 초점이 돌아갑니다.

| 팝업 | 안내하는 연락 수단 |
|---|---|
| `mdl-enroll` (입단) | 전화 · 문자 — `전화하기` / `문자 보내기` 버튼 |
| `mdl-charity` (자선 공연) | 전화 · 이메일 |

입단은 **전화·문자만** 안내합니다. 학부모 상담은 메일보다 전화가 빠릅니다.
자선 공연은 기관 담당자가 문서로 남기길 원하는 경우가 있어 메일도 함께 둡니다.

버튼을 새로 만들 때는 이렇게만 붙이면 됩니다.

```html
<button class="btn btn--solid" data-open="mdl-enroll">입단 문의</button>
<button class="btn"            data-open="mdl-charity">자선 공연 문의</button>
```

팝업 자체의 마크업은 5개 페이지 하단에 모두 들어 있습니다.
문구를 고치려면 `mdl__t` / `mdl__b` 를 페이지마다 같이 고쳐야 합니다.

## 사진

지금 **82장**입니다. 그 밖에 단원 사진 8장(`web/public/assets/img/members/`)과
영상 5개(`assets/video/`)가 따로 있습니다.

**파일 이름이 곧 날짜이자 분류입니다.** 규칙은
`web/public/assets/img/gallery/README.txt` 에 한 장으로 적어 두었습니다.

```
20250614-concert1-03.webp
└날짜───┘ └행사──┘ └번호┘
```

이름 앞이 날짜라 폴더를 이름순으로 두면 시간순으로 정렬됩니다.

> **원본은 `assets/img/_원본/` 에 폴더째 보관돼 있습니다.** 사이트는 webp 만
> 쓰므로 지우셔도 됩니다. 지우기 전에 다른 곳에 옮겨 두세요.

### 더 넣을 때

1. 사진 파일을 `web/public/assets/img/gallery/` 에 넣습니다.
2. `web/content/ 의 json 파일` 를 메모장으로 엽니다.
3. `window.GALLERY` 목록 **맨 앞**에 한 덩어리를 복사해 붙이고 값을 고칩니다.

```js
/* 공연장에서 찍은 사진 — 어느 공연인지만 적습니다 */
{ src:"web/public/assets/img/gallery/first-concert-stage.webp", ratio:"1170/780",
  title:"첫 공연 무대에 선 앙상블 전체",
  show:"regular-1", tag:"stage" },

/* 공연이 아닌 사진 — 종류와 날짜를 적습니다 */
{ src:"web/public/assets/img/gallery/practice-piano.webp", ratio:"540/285",
  title:"악보를 보며 피아노를 치는 손",
  tag:"practice", date:"2026.01", caption:"2026년 첫 연습" },
```

### 사진의 카테고리 — `show` 와 `tag`

사진마다 **어느 공연에서 찍었는지**와 **무슨 종류인지**를 답니다.
이 두 줄이 사이트의 세 가지 동작을 굴립니다.

| 칸 | 넣는 것 |
|---|---|
| `show` | 아래 `SHOWS` 의 `id`. 공연장에서 찍은 사진에만 답니다 |
| `tag` | 사진 종류 — `stage` `outreach` `practice` `group` `detail` |
| `date` | 파일 이름에 날짜가 없을 때만 씁니다. 보통 비워 둡니다 |

`show` 를 달면 이 세 가지가 자동으로 됩니다.

1. **Concert [지난 공연] 카드의 대표 사진** — 그 공연 사진 중 `GALLERY` 목록에서
   맨 앞에 있는 것. 대표 사진을 바꾸려면 그 사진을 목록 위로 옮기세요.
2. **공연별로 넘겨 보기** — 카드를 누르면 그 공연 사진이 차례로 넘어가고,
   다 넘기면 **다음 공연 사진으로 이어집니다.** 사진이 여럿인 카드에는
   오른쪽 아래에 `5장` 처럼 장수가 붙습니다.
3. **공연별 묶음** — 공연 사진이 한 덩어리로 이어집니다.

**날짜는 파일 이름에서 읽습니다.** 이름 앞 여덟 자리가 곧 날짜라서,
파일 이름을 고치고 `src` 한 줄만 맞추면 정렬이 따라옵니다. 같은 값을
두 군데 적어 두면 한쪽만 고치고 잊습니다.

> **사진 경로는 `GALLERY` 한 곳에만 적습니다.** 예전에는 `SHOWS` 에도 `src` 를
> 적어서 같은 사진이 두 군데 있었습니다. 한쪽만 고치고 잊기 쉬워서 `id` 로
> 잇는 방식으로 바꿨습니다.

**`tag` 는 지금 화면에 나오지 않습니다.** 분류만 해 둔 상태입니다 —
나중에 갤러리에 `[무대 / 연습 / 나눔]` 거르개를 붙일 때 바로 쓸 수 있습니다.

> ★ **연습 사진 17장은 날짜가 추정값입니다.** 원본 파일명에 날짜가 없어
> 실제로 연습한 날 중 하나를 골라 넣었습니다. `content.js` 의 그 줄들에
> "날짜 추정" 이라고 적어 두었으니, 아시는 건 파일 이름을 고치면 됩니다.

### 갤러리 — 탭과 정렬

`Gallery 페이지` 은 **사진 / 영상** 두 탭입니다. 처음에는 사진이 열립니다.
푸터의 `Gallery 페이지#videos` 로 들어오면 영상 탭이 열린 채 시작합니다.

탭 오른쪽에 정렬 고르개가 있습니다. **처음은 최신순**이고 **과거순**으로
바꿀 수 있습니다. 사진에만 쓰이므로 영상 탭에서는 숨습니다.

브라우저 기본 `<select>` 로 시작했다가 직접 만들었습니다 — 닫혀 있을 때는
CSS 로 꾸밀 수 있지만 **펼친 목록은 운영체제가 직접 그려서** 손이 닿지
않습니다(윈도우의 파란 선택 막대가 그것입니다).

홈 화면의 8장은 정렬하지 않고 `GALLERY` 목록 앞에서부터 그대로 씁니다.

- `ratio` — **사진의 실제 픽셀 크기를 그대로** 적는 게 가장 좋습니다
  (예: `"1170/780"`). 사진이 늦게 떠도 자리가 밀리지 않습니다.
  대충 적어도 됩니다 — 세로 `"3/4"`, 가로 `"4/3"`, 정사각형 `"1/1"`
- `title` — 화면에는 안 보이지만 **눈이 불편한 분에게 읽어주는 설명**입니다.
  사진에 무엇이 담겼는지 한 줄로 적어 주세요
- `caption` — 언제·어디. 지금 활동 사진에서는 화면에 나오지 않습니다
- `src` 를 비워두면 색 블록이 대신 나옵니다
- 목록 맨 앞이 사이트에서도 맨 앞에 나옵니다
- 홈에는 앞의 8장만, Gallery 에는 전체가 나옵니다

> `GALLERY` 목록은 **날짜 최신순**입니다(같은 날짜 안에서는 번호순).
> 홈에 나가는 앞 8장도 그 순서를 그대로 따릅니다 — 배치가 고르게
> 떨어지는 것보다 날짜 순서를 지키는 쪽을 택했습니다.

## 지난 공연 (연혁)

Concert 페이지 `#history` 의 목록입니다. `web/content/ 의 json 파일` 의 `window.SHOWS`
한 곳에서 옵니다 — 공연을 늘리거나 사진을 붙일 때 `Concert 페이지` 은 건드리지
않습니다.

```js
{ id:"concert1", date:"2025.06.14", title:"제1회 정기연주회", venue:"거암아트홀",
  note:"창단 공연", wide:true },
```

| 칸 | 넣는 것 |
|---|---|
| `id` | **사진과 잇는 이름표.** `GALLERY` 에서 `show:"concert1"` 로 가리킵니다 |
| `date` | 적은 그대로 나옵니다. `"2025.06"` 도 `"2025.06.14"` 도 됩니다 |
| `title` | 공연 이름 |
| `venue` | 장소. **모르면 비워 둡니다** — 빈 줄이 생기지 않습니다 |
| `note` | 부제. 제목 옆에 작은 이탤릭으로 붙습니다 |
| `wide` | `true` 면 두 칸을 차지합니다 |

> **여기에 사진 경로를 적지 않습니다.** 대표 사진은 `GALLERY` 에서
> `show` 가 이 공연을 가리키는 사진 중 **맨 앞의 것**이 자동으로 쓰입니다.
> 바꾸려면 그 사진을 `GALLERY` 목록 위로 옮기세요. 한 장도 없으면
> 로고 마크를 얹은 버건디 판이 들어갑니다.

목록 맨 앞이 사이트에서도 맨 앞입니다 — 최신 공연을 위에 둡니다.

### 벤토 격자 — 칸 수를 3의 배수로 맞춥니다

3단 격자입니다. `wide:true` 인 공연이 두 칸을 먹으므로, **칸 수 합이 3의 배수**면
줄 끝이 비지 않습니다. 지금은 7개 공연에 `wide` 두 개라 합이 9 — 3·3·3 으로
딱 떨어집니다.

```
1줄  [ 제2회 정기연주회        ]  [ 미앤코리아 ]
2줄  [ SFS ]  [ 연말 파티 ]  [ 도서관 12월 ]
3줄  [ 도서관 9월 ]  [ 제1회 정기연주회        ]
```

정기연주회 두 번을 큰 칸으로 뒀습니다. 한 해를 대표하는 무대라 위아래에서
섹션을 받쳐 줍니다. 공연을 더하거나 빼서 줄 끝이 비면 `wide` 를 옮기거나
꺼서 다시 맞추면 됩니다.

> **넓은 칸의 사진 비율 `8/3` 은 계산한 값입니다.** 좁은 칸은 406px 폭에
> `4/3` 이라 높이가 305px 입니다. 넓은 칸은 819px 이니 같은 높이가 되려면
> `819/305 = 2.69 ≈ 8/3`. 그래야 한 줄 안에서 사진 아랫변과 글줄이 나란히
> 섭니다. `16/9` 로 두면 넓은 칸만 460px 로 커져서 옆 칸 글 아래가 휑하게
> 빕니다. 가로는 그대로 두고 위아래만 자르므로 단원이 옆으로 잘려 나가지
> 않습니다 — 무대 사진에서는 이쪽이 안전한 자르기입니다.

좁은 화면에서는 `wide` 가 저절로 풀립니다 — 900px 아래는 2단, 520px 아래는
1단이 되고 모든 칸이 같은 `4/3` 이 됩니다.

사진을 넣으면 눌러서 크게 볼 수 있게 됩니다. 좌우 화살표는 **사진이 있는
공연끼리만** 넘어갑니다(포스터·활동 사진 쪽으로 넘어가지 않습니다).

## 포스터 추가하기

Concert 페이지의 **지난 공연 포스터** 입니다. 장수는 자유입니다.

1. 포스터 파일을 `web/public/assets/img/poster/` 에 넣습니다.
2. `web/content/ 의 json 파일` 의 `window.POSTERS` 를 고칩니다.

```js
{ src:"web/public/assets/img/poster/2026-second-concert.webp", ratio:"3/4",
  title:"제2회 정기연주회", caption:"When Melodies Meet · 2026. 6. 21. 로데아트센터" },
```

### 이미지는 webp 로 넣습니다

지금 들어 있는 두 장은 PNG 원본을 **webp 품질 85** 로 바꾼 것입니다.
1,175KB → 100KB, **91% 줄었습니다.** 가장 작은 후원사 글씨까지 원본과 구분되지
않습니다(PSNR 41dB). 원본 PNG 는 같은 폴더에 남겨두었으니 지우셔도 됩니다.

새 포스터를 넣을 때 변환이 필요하면 말씀해 주세요. 파일 이름은 한글·띄어쓰기
대신 영문 소문자로 두었습니다 — 주소에 그대로 들어가는 값이라 서버에 따라
인코딩이 어긋날 수 있습니다.

> 두 장 모두 가로 640~690px 입니다. 목록에서는 충분하지만 크게 볼 때
> 고해상도 화면에서는 살짝 무릅니다. 원본 파일이 더 크게 있으면 그걸로 바꾸는
> 편이 좋습니다.

- **미리보기는 높이를 3/4 로 맞춥니다.** 비율이 제각각이어도 나란히 놓았을 때
  높이가 같습니다. 잘린 부분은 눌러서 크게 보면 전부 나옵니다.
- 3/4 을 고른 이유 — 포스터는 맨 위(소제목)와 맨 아래(날짜·장소·후원사)에
  정보가 몰려 있어서 **세로가 잘리면 그게 날아갑니다.** 3/4 은 지금 두 장 중
  세로로 긴 쪽보다 아주 조금 넓어서 가로만 자릅니다
  (제2회 세로 0.7% / 창단 가로 6.0%). 세로로 더 긴 포스터가 들어오면
  `style.css` 의 `.poster__ph` 에서 `aspect-ratio` 를 낮추세요.
- `ratio` 는 **크게 보기에서 사진이 아직 없을 때** 자리 표시 블록의 비율입니다.
  미리보기 비율과는 상관없습니다.
- `src` 를 비워두면 *"포스터 이미지를 넣어주세요"* 안내가 대신 나옵니다.
- 누르면 활동 사진과 같은 창으로 크게 열립니다. 좌우 화살표는 포스터끼리만
  넘어갑니다 — 사진 쪽으로 넘어가지 않습니다.

> 크게 보기가 뜨려면 그 페이지에 `<div class="lb">` 덩어리가 있어야 합니다.
> 지금은 `index` · `gallery` · `concert` 세 페이지에 들어 있습니다.

## 영상 추가하기

세 가지를 받습니다. `web/content/ 의 json 파일` 의 `window.VIDEOS` 에 한 덩어리씩 붙입니다.
**어느 쪽이든 썸네일을 누를 때까지 아무것도 불러오지 않습니다.** 페이지가 처음
열릴 때 느려지지 않고, 누르기 전에는 유튜브·인스타그램에 요청이 가지 않습니다.

### 1. 유튜브

주소에서 `v=` 뒤의 값이 `id` 입니다.

```
https://www.youtube.com/watch?v=AbCdEfGh123   →   id 는 AbCdEfGh123
```

```js
{ id:"AbCdEfGh123", title:"2026 정기 연주회", meta:"전곡 · 1부 / 2부", thumb:"" },
```

`thumb` 을 비워두면 유튜브 썸네일을 자동으로 가져옵니다.

### 2. 인스타그램 — 주소만 붙여넣기

게시물 주소를 통째로 `ig` 에 적습니다. 릴스도 같습니다.

```js
{ ig:"https://www.instagram.com/reel/XXXXXXXXXXX/",
  thumb:"web/public/assets/img/gallery/practice-tutti-piano.webp",
  title:"오늘도 연습", meta:"연습실" },
```

**`thumb` 을 꼭 적어 주세요.** 인스타그램은 공개 썸네일 주소를 주지 않아서,
비워 두면 표지가 빈 색면이 됩니다. 갤러리 사진 중 한 장을 고르면 됩니다.

알아 둘 것:

| | |
|---|---|
| 공개 게시물만 | 비공개 계정이면 아무것도 안 나옵니다 |
| 인스타그램 화면이 그대로 | 계정 이름·좋아요·캡션이 함께 들어옵니다. 사이트 카드처럼 깔끔하진 않습니다 |
| 높이가 게시물마다 다름 | 인스타그램 스크립트가 스스로 정합니다. 16:9 틀을 씌우지 않았습니다 |
| 추적 코드 | 누른 뒤 인스타그램 스크립트를 받아옵니다. 누르기 전에는 요청이 없습니다 |
| 게시물을 지우면 | 사이트에서도 사라집니다 |

> **왜 iframe 을 직접 못 쓰나.** `instagram.com/reel/…/embed/` 를 iframe 에
> 걸면 될 것 같지만, 인스타그램이 `X-Frame-Options: DENY` 를 보내서 브라우저가
> 프레임을 거부합니다(2026-08 확인). 인스타그램이 공식으로 열어 둔 길은
> `blockquote` + `embed.js` 한 가지뿐이라 그 방식으로 붙였습니다.

### 3. 직접 올린 영상 (권장)

파일을 `assets/video/` 같은 곳에 두고 경로를 적습니다.

```js
{ mp4:"assets/video/encore.mp4",
  thumb:"web/public/assets/img/gallery/first-concert-stage.webp",
  title:"앵콜곡", meta:"첫 공연" },
```

인스타그램에 올린 영상이라면 **올릴 때 쓴 원본 파일**을 그대로 쓰면 됩니다.
남의 서비스에 기대지 않고, 인스타그램 UI 없이 사이트 카드 모양 그대로 나오고,
게시물을 지워도 살아 있습니다. 1~2MB 짜리 릴스 길이면 부담도 없습니다.

## 히어로 사진 넣기

**`assets/img/hero.jpg` 라는 이름으로 파일을 넣기만 하면 됩니다.** HTML 은 고치지 않습니다.

가로로 긴 합주 사진이 잘 맞습니다. 2000px 이상 권장.
파일이 없는 동안에는 버건디 그라디언트가 대신 나옵니다 — 사진 층만 그려지지 않고
그 아래 층이 그대로 보이는 구조라서, 없어도 화면이 깨지지 않습니다.

다른 이름을 쓰고 싶으면 `홈` 의 `.hero__bg` 에 인라인으로 붙이면
CSS 를 덮어씁니다.

```html
<div class="hero__bg" style="background-image:url('assets/img/다른이름.jpg')"></div>
```

### 상단 바가 사진 위에 겹칩니다

홈에서는 상단 바가 배경 없이 사진 위에 얹히고, 아래에 흰 실선 한 줄만 그어집니다.
사진이 밝아도 흰 글씨가 읽히도록 상단에 옅은 그늘을 깔았고, 글자와 마크에는
그림자를 따로 주었습니다. 40px 넘게 내리면 흰 배경으로 바뀝니다.

서브페이지는 처음부터 흰 배경입니다. 이 동작은 `<body data-hdr="...">` 로 정합니다.

```html
<body data-hdr="overlay">   <!-- 홈: 사진 위에 겹침 -->
<body data-hdr="solid">     <!-- 서브: 흰 배경 -->
```

아이들 실명은 사이트 어디에도 없습니다. 지난 공연 프로그램의 연주자 표기도
`Violin — 솔로`, `Cello — 2중주` 처럼 **편성만** 적었습니다.

모집 파트를 보여주던 `About 페이지#parts` 는 지금 없습니다. 다시 두고 싶으면
About 에 섹션을 만들고 푸터의 [연주한 곡] 자리에 링크를 넣으면 됩니다.

> `About 페이지#repertoire` 끝에 `Piano 반주` 를 적어둔 자리가 있습니다.
> 반주자가 성인 지도교사라면 성함을 넣어도 됩니다. 확인이 필요합니다.

## 연주한 곡 목록은 About 에 있습니다

`About 페이지#repertoire`. 원래 Concert 의 **지난 정기 연주회 프로그램** 이었는데,
한 공연의 순서표가 아니라 **지금까지 아이들이 무대에 올린 곡이 쌓인 목록**이라서
About 으로 옮겼습니다. 그래서 표현도 바꿨습니다.

| | 전 (Concert) | 후 (About) |
|---|---|---|
| 제목 | 지난 정기 연주회 프로그램 | 지금까지 연주한 곡 |
| 묶음 | 1부 / Intermission / 2부 | 아는 곡으로 시작해서 / 여기까지 왔습니다 |
| 순서 | 그날 연주한 차례 | 익숙한 곡 → 클래식·탱고 |

바로 위 **아는 곡으로 시작합니다** 단락이 말한 것을 이 목록이 증명하는 자리라서
그 아래에 붙였습니다. 곡 수는 15곡, 옮기면서 빠뜨린 곡은 없습니다.

### 조판은 공연 프로그램 방식입니다

곡 이름 아래에 작곡가, 두 단 구성. **한 단이 한 묶음**입니다.
색은 새로 만들지 않고 푸터의 버건디 블랙(`--ground`)과 `--on-ground`(골드) 를 그대로 씁니다.
가운데 장식은 새 그림이 아니라 **로고 마크**(`--mark`)를 실선 사이에 놓은 것입니다.

밝은 배경으로 되돌리려면 섹션에서 `sec--dark` 한 단어만 빼면 됩니다.

곡을 추가할 때는 `prog__i` 한 덩어리를 복사해 붙입니다.

```html
<div class="prog__i">
  <p class="prog__t">곡 이름 <em>부제</em></p>
  <p class="prog__c">작곡가</p>
  <p class="prog__e">Violin — 솔로</p>   <!-- 편성. 아는 곡에만 붙입니다 -->
</div>
```

`prog__e`(편성)는 **아는 곡에만** 답니다. 지난 프로그램에 표기가 있던 4곡뿐이고,
나머지에 "전체 합주"라고 적지 않았습니다 — 확인된 사실이 아닙니다.

> 두 단의 곡 수가 9 : 6 이라 오른쪽 아래가 비어 보입니다. 묶음이 곧 단이라
> 생기는 일입니다. 균형을 맞추려면 곡을 어느 묶음에 넣을지 다시 정하면 됩니다.

> 옮기면서 `Concerto for Two Violins in Minor` 를 `in D minor` 로 고쳤습니다.
> BWV 1043 은 라단조입니다. 조성 표기가 빠져 있었습니다.

## 상단 내비 — 따라오는 밑줄

현재 페이지 아래 그어져 있는 선이 **마우스를 올린 항목으로 미끄러져 갑니다.**
벗어나면 원래 자리로 돌아옵니다. 선은 하나뿐입니다.

- 홈과 개인정보처리방침에는 자기를 가리키는 내비 항목이 없습니다.
  이 두 화면에서는 선이 평소에 숨어 있다가, 올려놓으면 그 자리에 켜지고
  벗어나면 다시 사라집니다.
- 키보드 `Tab` 으로 이동해도 똑같이 따라갑니다.
- 예전에 있던 "hover 하면 흐려지는" 효과는 뺐습니다. 선이 반응하는데
  글자까지 흐려지면 서로 어긋납니다. 로고에만 남겨두었습니다.
- 움직임을 끈 분(`prefers-reduced-motion`)에게는 미끄러지지 않고 즉시 옮겨집니다.

선은 `main.js` 가 만들어 붙입니다. 6개 파일의 마크업을 건드리지 않으려고
이렇게 했습니다. **스크립트가 실행되지 않으면 예전처럼 현재 항목에 선이
고정으로 남습니다** — 기능이 사라지지 않습니다.

미끄러지는 속도는 `style.css` 의 `.nav__ind` 에 있습니다.

```css
transition:transform 280ms cubic-bezier(.22,.61,.36,1), … ;
```

밑줄이 아예 없는 편이 낫다면 `main.js` 의 `[상단 내비]` 블록을 지우고
`style.css` 의 `.nav a[aria-current="page"]` 한 줄도 지우면 됩니다.

## 로고

상단 바 왼쪽은 두 덩어리입니다. 6개 파일에 같은 마크업이 들어 있습니다.

```html
<a class="hdr__logo" href="홈">
  <span class="hdr__mark" aria-hidden="true"></span>   <!-- 마크 -->
  <span class="hdr__wm">Ensemble M.A.Y</span>          <!-- 워드마크 -->
</a>
```

### 마크는 그림 파일이 아니라 CSS 안의 SVG 입니다

`web/app/style.css` 맨 위 `--mark` 한 줄이 전부입니다. 이유가 두 가지입니다.

1. 마크는 자리마다 색이 달라야 합니다. 사진 위에서는 흰색, 흰 배경에서는
   잉크색입니다. CSS 마스크로 넣으면 글자색을 그대로 따라갑니다.
2. HTML 파일을 브라우저로 그냥 열었을 때(`file://`) 크롬이 외부 파일 마스크를
   막습니다. 이 사이트는 서버 없이도 열려야 하므로 주소가 없는 형태로 넣었습니다.

원본은 **`web/public/assets/img/icon/logo-emblem.png`** (917×904, 투명 PNG) 입니다.
`--mark` 는 그 **알파(투명도)만 256px 로 줄여 넣은 것**입니다.

> **왜 SVG 가 아니라 PNG 인가.** 받은 `logo.svg` 두 벌 모두 아래쪽 이중 아치가
> **패스 단계에서 잘려** 있었습니다 — 하나는 바닥이 평평하게 잘렸고, 다른
> 하나는 양옆에서 끊겨 가운데가 비었습니다. 아트보드 크기 문제가 아니라
> 도형 자체가 잘린 상태로 저장된 것입니다. 온전한 도안은 이 PNG 뿐이라
> 이걸 씁니다.
>
> **온전한 SVG 를 받으면** `--mark` 한 줄만 갈아 끼우면 됩니다. 디자이너분께는
> "아치를 클리핑 없이 온전한 곡선으로 만든 뒤 내보내 달라"고 전하시면 됩니다.

> **256px 인 이유** — 이 마크가 화면에서 가장 크게 쓰이는 곳이 54px 이라,
> 3배 고해상도 화면(162px)까지 감당하고도 남습니다. 더 키우면 CSS 파일만
> 무거워집니다. 파비콘은 이 PNG 원본(917px)에서 따로 굽습니다.

> **둘레 글자는 작은 크기에서 읽히지 않습니다.** `MUSICALLY ACCOMPANIED YOUTH`
> 는 32px 에서 획이 1px 도 안 돼 흐린 고리로 보입니다. 그래서 마크 자리를
> 예전(32px)보다 키워 **52px** 로 뒀습니다 — 도장처럼 읽히는 크기입니다.

크기는 `.hdr__mark` 의 `width` / `height` 두 줄입니다. **비율 917:904 를 지키세요.**

```css
.hdr__mark{ width:52px; height:51px }   /* 데스크톱 */
.hdr__mark{ width:44px; height:43px }   /* 520px 이하 */
```

> **`mask` 단축 속성으로 쓰지 마세요.** `mask: … center/contain` 로 적으면
> 크기(`contain`)를 무시하는 브라우저가 있어, 마크가 제 크기로 그려지고
> 칸 밖이 잘립니다. 낱개 속성(`mask-image` · `mask-size` …)으로 적어 두었습니다.

## 브랜드 색 바꾸기

`web/app/style.css` 맨 위 `--brand` 한 줄만 고치면 사이트 전체가 따라옵니다.

```css
--brand:#4A1F24;   /* 딥 버건디 (현재) */
--brand:#5B4C3D;   /* 브라운 */
--brand:#4A5C3D;   /* 신록 */
--brand:#32483D;   /* 딥그린 */
```

버튼, 사진 자리, 테두리, 더보기 링크까지 모두 이 값에서 파생됩니다. 고칠 곳은 이 한 줄뿐입니다.

### 팔레트 (버건디 + 앤틱골드)

| 토큰 | 값 | 쓰이는 곳 | 흰 배경 명암비 |
|---|---|---|---|
| `--brand` | `#4A1F24` | 버튼 · 라벨 · 더보기 글자 · CTA 밴드 | 13.9:1 |
| `--ink` | `#3E3436` | 본문 | 12.0:1 |
| `--ink-mid` | `--ink` 78% | 보조 텍스트 | 6.1:1 |
| `--accent-gold` | `#C9A66B` | **선과 아주 작은 글자만** | 2.3:1 — 글자로 쓰면 안 됨 |
| `--ground` | `#2A1418` | 푸터 바닥 · 연주 목록 배경 | 17.3:1 (흰 글자) |
| `--on-ground` | = 골드 | 어두운 바닥 위 소형 캡스 | 7.6:1 (바닥 대비) |

### 골드를 쓰는 자리

골드는 **면이 아니라 선**입니다. 넓게 깔면 값싸 보입니다. 나오는 곳은 여기가 전부입니다.

```
히어로 눈썹·영문 글자    .btn--ghost 테두리·글자   .more 밑줄
.cta p 글자             .cta__2nd 글자·밑줄       .card--lead 테두리
.orn 구분선과 마크        .foot 위 헤어라인
--on-ground → .foot__en · .foot__sns · .prog__e · .prog__g
```

**흰 배경 위 골드는 2.3:1 입니다.** 그래서 흰 바탕에 놓이는 골드는 전부 1px 선이고,
글자로 쓰는 곳은 전부 어두운 바탕 위입니다 — 히어로(5.1:1), CTA 밴드(6.1:1),
푸터·연주 목록 바닥(7.6:1).

### 히어로가 예전보다 어두워진 이유

히어로는 단색이 아니라 **사진 위**입니다. `[작은 골드 글자 → 큰 흰 제목 → 골드 테두리
버튼]` 배치를 여기에도 넣으면서 `.hero__veil` 을 함께 올렸습니다.

지금 사진(밝은 연주홀)은 영문 줄과 버튼 줄에 **완전히 흰색으로 날아간 픽셀(L 0.99)** 이
걸립니다. 예전 베일(`.55/.46/.62`)에서 그 자리의 골드는 **1.7:1** — 못 읽습니다.
골드가 4.5:1 을 넘기려면 그 줄의 가림막이 **0.75** 는 되어야 합니다.

위아래를 통째로 올리면(`.81/.72/.88`) 사진이 실루엣만 남아서, **글이 놓이는 세로
30~70% 구간만** `.78` 로 눌렀습니다. 맨 위(`.62`)와 맨 아래(`.66`)는 덜 눌러서
정작 보여줄 것 — 아래쪽 단원들과 무대 바닥 — 이 덜 어두워집니다.

측정값(1440×750 · 768×750 · 390×600 세 경우 모두 미달 면적 0%):

| 요소 | 색 | 최저 명암비 |
|---|---|---|
| 눈썹 `Ensemble MAY` | 골드 | 5.8~6.1:1 |
| 제목 두 줄 | 흰색 | 12.7~12.9:1 |
| 영문 한 줄 | 골드 | 5.1:1 |
| 버튼 테두리·글자 | 골드 | 5.1:1 |

> **사진을 더 밝게 되돌리려면** `.hero__veil` 가운데 두 값(`.78`)을 낮추세요.
> 그만큼 골드가 내려갑니다 — `.70` 이면 3.6:1, `.64` 면 2.9:1 로 AA 미달입니다.
> 그때는 히어로 글자를 흰색으로 되돌리는 편이 낫습니다
> (`.hero .eyebrow` 와 `.hero__en` 의 `color` 두 줄).

> **`.btn--ghost` 에 흰 반투명 바탕을 다시 깔지 마세요.** `rgba(255,255,255,.16)`
> 하나만 깔아도 그 아래 배경이 밝아져서 골드 글자가 4.5:1 → **2.7:1** 로 떨어집니다.

- 제목·명조 — **본명조 (Noto Serif KR)** (Google Fonts). 가변 폰트 400~700.
- 본문 — **Pretendard Variable** (jsDelivr). 굵기 450을 기본으로 씁니다.
- 영문 — 스택에 Poppins가 들어 있습니다. rosha와 같은 선택입니다.
- **상단 바 — 워드마크와 내비 모두 명조 400** 입니다. 마크의 가는 선과
  같은 결로 맞추려고 고딕에서 바꿨습니다. 고딕으로 되돌리려면 `style.css`
  의 `.nav a` 에서 `var(--myeongjo)` 를 `var(--gothic)` 으로 바꾸세요.

### 나눔명조에서 본명조로 바꿨습니다

나눔명조는 **인쇄용으로 만들어진 활자**입니다. 15px 쯤 되면 가로획이 화면 픽셀에
못 앉고 사라져서, `문어의 꿈` 이 `분어의 꿈` 처럼 보였습니다. 폰트 자체의 한계라
CSS 로 보정할 수 없습니다.

본명조는 화면용으로 힌팅된 가변 폰트라 같은 크기에서 획이 버팁니다.

**굵기 규칙** — 옮기면서 전부 다시 잡았습니다.

| 자리 | 나눔명조 | 본명조 | 이유 |
|---|---|---|---|
| 작은 한글 (≤18px) | 400 | **500** | 획이 날아가던 구간 |
| 큰 글씨 (30px~) | 400 | 400 | 이미 충분히 굵음 |
| 제목 | 700 | **600** | 본명조 700 은 나눔 700 보다 확연히 무거움 |
| 상단 바 | 400 | 400 | 라틴 글자뿐이라 원래 안 깨지던 곳 |

본명조가 나눔명조보다 글자 폭이 넓습니다. 히어로 `max-width` 를 `58ch` 에서
`580px` 로 바꿨습니다 — `ch` 는 본문 고딕 기준이라 실제로는 444px 밖에 안 됐고,
둘째 줄이 밀려 `다.` 만 셋째 줄로 떨어졌습니다.

전송량은 about 기준 943KB → 1030KB (+9%) 입니다. 파일 개수는 41개 → 32개로
줄었습니다(가변 폰트라 굵기별로 따로 받지 않습니다).

### 쓰지 않은 보정법

| 방법 | 왜 안 썼나 |
|---|---|
| `-webkit-font-smoothing:antialiased` | **맥에서 획을 더 얇게 만듭니다.** 서브픽셀 렌더링을 끄는 속성이라 증상이 심해집니다. 이 사이트는 원래 이것 때문에 제거한 이력이 있습니다 |
| `-webkit-text-stroke:0.2px` | 크롬·사파리 전용. 획을 안팎으로 같이 굵혀서 15px 명조에서는 `ㅁ`·`ㅇ` 속공간이 메워집니다 |
| `text-shadow` 로 번지게 | 어두운 푸터·히어로에서 흰 글자에 후광이 생깁니다. 증상만 가리는 방법입니다 |

원래 목표한 조합은 **아리따부리**(제목) + **마포꽃섬**(본문)입니다.
`.woff2` 파일을 `assets/fonts/` 에 넣고 `style.css` 상단의 `@font-face` 주석을 해제하면 됩니다.
스택 맨 앞에 이미 이름이 들어가 있어서 파일만 넣으면 자동으로 우선 적용됩니다.

> 두 폰트 모두 무료 배포지만 **웹폰트 임베딩 조항**은 각 라이선스 원문 확인이 필요합니다.

### 왜 rosha와 수치가 다른가

rosha의 본문은 `13px` / 굵기 `normal` 입니다. 그대로 옮겼더니 획이 끊겨 보였습니다.
rosha는 본문에 **마포꽃섬(고딕)** 을 쓰는데 우리는 명조 제목 + 시스템 고딕 조합이라
같은 수치에서 훨씬 얇게 렌더됩니다.

| 항목 | rosha | 우리 | 이유 |
|---|---|---|---|
| 본문 | 13px / 400 | **14px / 450** | 13px 명조·고딕 혼용에서 획이 끊김 |
| 섹션 제목 | (테마 기본) | **600** | 명조 400은 흰 배경에서 흐릿함 |
| 보조 텍스트 | — | **불투명도 .78 고정** | 흰 배경 6.1:1 · 틴트 5.9:1. AA(4.5:1) 아래로 내려가는 지점은 .62 |
| 히어로 | — | 32px + 그림자 | 밝은 글자는 어두운 배경에서 더 얇아 보임 |

`-webkit-font-smoothing:antialiased` 는 쓰지 않습니다. 획을 가늘게 만드는 주된 원인입니다.

## 등장 애니메이션

`홈` 전체와 `About 페이지` 의 연주 목록, `Gallery 페이지` 의 사진첩에 적용했습니다.

- **히어로** — 페이지가 열릴 때 눈썹 → 제목 → 영문 → 버튼 순으로 올라옵니다 (0.2s ~ 0.68s)
- **히어로 배경** — 스크롤한 만큼의 **0.4배**로 사진이 따라 내려옵니다. **20px 에서 멈춥니다**
- **각 덩어리** — 화면에 12% 들어오면 14px 아래에서 올라옵니다. 한 번만 재생됩니다
- **목록 안 항목** — 곡 한 줄, 사진 한 장이 차례로. 11px / 0.58s 로 덩어리보다 조금 얕게
- 이동 거리를 14px로 짧게 잡았습니다. 크게 움직이면 값싸 보입니다
- `prefers-reduced-motion` 을 켠 분에게는 모두 정지 상태로 보입니다 (패럴랙스는 아예 붙지 않습니다)

붙이거나 떼는 방법은 속성 하나입니다.

```html
<div class="wrap" data-reveal-group="80">   <!-- 덩어리가 80ms 간격으로 -->
<div class="rep"  data-reveal-seq="70">     <!-- 항목이 70ms 간격으로 -->
<div class="mas"  data-reveal-seq="40">     <!-- 사진이 40ms 간격으로 -->
<div class="wrap">                          <!-- 애니메이션 없음 -->
```

**둘은 겹쳐 쓸 수 있습니다.** 어떤 덩어리가 스스로 `seq` 이거나 그 안에 `seq` 를
품고 있으면, 그 덩어리는 통째로 뜨지 않고 안쪽 항목이 하나씩 뜹니다. 겹쳐 띄우면
바깥이 흐린 동안 안쪽도 흐려서 두 번 페이드하는 것처럼 보이기 때문입니다.
안쪽이 다 나온 뒤에 다음 형제로 넘어가서, 목록 아래 `[더보기]` 가 마지막 줄보다
먼저 나오는 일이 없습니다. 실제로 계산되는 시각은 이렇습니다.

```
홈 · 레퍼토리     제목 0 → 곡 80·150·220·290·360 → 전체 보기 430ms
홈 · 사진첩       눈썹 0 → 제목 80 → 사진 160…440(40ms 간격) → 더보기 480ms
about · 연주 목록  제목 0 → 안내 80 → 장식 160 → 두 단이 나란히 240…720ms
gallery · 사진첩   0…440ms (12장)
```

지연은 한 묶음 안에서 480ms, 겹쳐 써도 760ms 에서 끊습니다. 뒤쪽이 너무 늦게
나타나면 답답합니다.

> 목록은 **항목마다가 아니라 덩어리 하나를 지켜봅니다.** 항목마다 따로 지켜보면
> 목록이 화면보다 길 때 뒤쪽 항목이 눈에 들어온 뒤에도 제 지연시간만큼 더
> 기다렸다 나타나서 굼떠 보입니다.

서브페이지에도 넣고 싶으면 같은 속성을 그 페이지 `.wrap` 에 붙이면 됩니다.

## 배포 (Cloudflare Pages)

도메인과 DNS가 이미 Cloudflare에 있으므로 Cloudflare Pages가 가장 간단합니다.

1. Cloudflare 대시보드 → Workers & Pages → Create → Pages
2. 빌드 설정 없음 (Framework preset: None, Build command 비움, Output directory `/`)
3. 이 폴더를 그대로 업로드하거나 Git 저장소를 연결
4. Custom domain 에 `ensemblemay.com` 연결 → DNS 레코드는 자동 생성

현재 Zone File 이 비어 있어 충돌 없이 바로 붙습니다.
